{% comment %} The settings popover, shared verbatim by both pages (index.html and mastery_costs.html): a cog button pinned top-right toggles a panel holding EVERY parameter except the solver page's own Goal pane -- the pasted game state, the frontier limits, and all the preference panes. Edits inside it are staged: nothing is saved and nothing re-solves until Save (Cancel/Escape/the x/an outside click revert to the values the panel opened with). See settings.js, whose initSettings() wires all of this and whose readSettingsParams/applySettingsParams own every id below. EVERY control mirroring a config.toml key carries `data-config-key` (the dotted key) and `data-config-type` (int/float/text/date/bool), whether it is generated from settings.js's schemas or hand-written below -- so an external tool (a browser extension scraping the game, say) can find a field by what it *means* rather than by CSS id, and coerce its value. Write to one the way a user would (set `.value`/`.checked`, then dispatch `input` + `change`) and press Save. The hand-written ones additionally carry `data-config-own-param`: their value travels to the server under its own request param, not the generic `config` object, so readConfigParams/applyConfigParams skip them. Nothing outside those two functions cares about the distinction. Controls with no `data-config-key` at all are the ones with no config key to mirror: the paste boxes, cookie sets (read from the pasted inventory), and everything under Limits. Each pane wraps its content in a `.pane-body` div: that wrapper is the grid that lays the field rows out in two columns when the popover is wide enough (see style.css), so a new pane needs it too. Tag a row `.field-row wide` when it holds more than one control after its label and shouldn't be squeezed into one column. Both pages must inject the bundled config defaults (the `{{ config_defaults|json_script:"config-defaults" }}` script) -- every `.config-fields[data-config=...]` div below (Farming / Exploring / Fishing / Effectiveness / Pets / Buildings, plus the generated rows inside Resources and Trading values) and the material-trading list are generated from it. {% endcomment %}

Limits

Which plans the frontier shows, and how they are spread. These shape the solver page's plan list only — the mastery-costs table always reports each mastery's fastest plan.

Fishing

Perks and meals setting how many fish one Large Net catches. (The Sinking Swamp fishing zone is unlocked by the Swamp Puzzle, under Exploring — it gates the exploring location too.)

Exploring

Perks and meals setting how much one Arnold Palmer yields and how far an Apple Cider's stamina goes, plus the unlocks changing what a zone drops or whether you can enter it at all. Auto-detect reads each of those from your pasted inventory.

Exploring effectiveness

Per-zone Exploring Effectiveness driving how many explores one Apple Cider does. Blank uses the bundled default.

Pets

Each pet's current level (tier items come from the game data). Blank uses the bundled default.

Buildings

Passive-production buildings. Blank uses the bundled default.

Trading values

Gold trade prices used to rank plans by real cost. Arnold Palmer, Apple Cider, Orange Juice, Large Net and Hickory Omelette are priced per 1,000 units; Cookie Set and Pumpkin Juice are gold each. Blank uses the bundled default.

Material trading

Which raw materials the plan may trade for (buy with) Arnold Palmers, and the price it assumes. Untick anything you would not actually trade — a material nobody spare-trades, or one you would only ever buy at a price not worth your time — so plans lean only on trades you would really make. Prices are in AP per 1,000 units; the greyed range is the going rate as a guide, but you can enter any price.
